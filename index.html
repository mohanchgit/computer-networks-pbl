Why bytes differ: Ethernet headers are link-local and are rebuilt for each routed link. The IP source and destination generally remain the same end-to-end, while the IPv4 TTL decreases at each router hop. The transport/application payload can remain identical. A router may also update the IPv4 header checksum. Switches normally forward Ethernet frames without decrementing IP TTL; a router does.

Teaching simplification: addresses, TTL, checksums, and frame fields are illustrative. Real captures depend on VLANs, NAT, tunnels, IPv4/IPv6, encryption, and where capture occurs. The router changes Ethernet framing; the TTL example assumes IPv4.

2 · Why layering exists at all

Layering is an engineering and scaling strategy, not just a diagram to memorise.

The design problem

Imagine N application types need to work across M physical network technologies.

Without a shared layer
20

Application × link integrations

With a common layer
9

Application + link interfaces

A shared layer reduces the number of integration relationships in this simplified model.

What changes when a new link appears?

Without layering

Every application may need another implementation or adaptation for the new link technology.

With layering

Implement the common interface for the new link; applications above it can continue using the shared service.

Key idea: Layering creates stable interfaces. Each layer can evolve behind its interface, reducing how much other parts of the system must change.

Connection to later topics: Message brokers and middleware can solve a similar integration problem by allowing many producers and consumers to communicate through a shared interface.

3 · The Internet's narrow waist: IP

One common network-layer protocol connects many applications to many link technologies.

Best-effort packet delivery across interconnected networks. IP does not promise delivery, ordering, or duplicate suppression.

Ethernet / copper
Wi-Fi / radio
Fibre
Satellite / mesh
Why “narrow waist”? Many upper-layer services can use IP, and many different link technologies can carry IP packets. Each side needs to agree on the IP interface, not on every possible application-to-link pairing.

Above IP

Applications and transport protocols decide what extra properties they need, such as reliable delivery or request semantics.

IP itself

Forwards packets on a best-effort basis. Packets may be lost, duplicated, or arrive out of order; corruption detection and handling depend on the relevant protocol and layer.

Below IP

Link technologies move frames across a local link using technology-specific addressing and framing.

4 · The end-to-end argument

Put functions where they can be implemented correctly and evolved independently.

Explore a reliability requirement

Suppose an application must know whether a complete reading was received correctly by the intended service.

Use an application-level acknowledgement or response that confirms the service received and accepted the reading. Link-level checks alone cannot establish the full application outcome.

What “end-to-end” does—and does not—mean

It means: some guarantees can only be fully checked at the endpoints, because intermediate links cannot know the application's complete goal.

It does not mean: routers and links are useless, or that reliability, security, and congestion control belong only in applications. Lower layers still provide important local functions.

Example: Ethernet can detect some frame errors on a local link, and TCP can provide reliable ordered delivery between transport endpoints. An application may still need to confirm that a database stored the reading or that a business action completed.
